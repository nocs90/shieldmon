# Try ShieldMon locally

A 15-minute walkthrough of the whole lifecycle — scan, triage, risk acceptance, a fix
proven by evidence, the monthly report — on your machine, with no Docker daemon and
nothing touching your real data directory.

The trick: a throw-away **local OCI registry** where you control a tag. (With Docker
installed, [manual-testing.md](manual-testing.md) does the same with real `docker build`s.) You publish an old
image as `demo/app:prod`, then "ship a fix" by moving the tag to a patched image, exactly
as a CI pipeline would.

## 0. Prerequisites

- Go ≥ 1.27, and `syft`, `grype`, `trivy` in `PATH` (`shieldmon doctor` checks them).
- Network access to Docker Hub and to the vulnerability DB mirrors.

```sh
make build
go build -o bin/crane github.com/google/go-containerregistry/cmd/crane   # registry + copy tool

export DEMO=/tmp/shieldmon-demo                                         # isolated data dir
alias sc='./bin/shieldmon --data-dir $DEMO --config $DEMO/config.yaml'
sc init                # on macOS, which has no sandbox backend: sc init --sandbox none
sc doctor              # with --sandbox none it fails on "sandbox none": expected
```

## 1. Start a local registry (separate terminal)

```sh
./bin/crane registry serve --address localhost:5555
```

It is in-memory: stopping it erases everything. `localhost` registries are spoken to over
plain HTTP automatically.

## 2. Publish a vulnerable "release"

```sh
./bin/crane copy --platform linux/amd64 alpine:3.18.0 localhost:5555/demo/app:prod
sc scan localhost:5555/demo/app:prod
```

Expect: SBOMs generated by syft and trivy, ~60 findings, most confirmed by both scanners.

```sh
sc findings list --severity high          # what matters
sc findings show 1                        # details + audit trail
sc sbom list 1                            # stored SBOMs: target ID, image ref or digest prefix
sc targets list
```

Run `sc scan localhost:5555/demo/app:prod` again: it is a **rematch** (no image pull,
seconds instead of a full scan) — SBOM-first in action.

## 3. Triage like a team would

```sh
sc findings triage <ID> --note "bump base image"
sc findings remediate <ID>
sc findings accept-risk <ID> --author you \
   --justification "service processes no untrusted input; RISK-1"     # expires at the SLA deadline
sc findings accept-risk <ID> --deviation vendor-dependency --author you \
   --justification "vendor will not fix; reviewed monthly"            # only for findings without a fix
sc findings untriage <ID>                 # undo a triage
```

Try to cheat: there is no command to mark a finding fixed, and decisions without a
justification or an author are refused — as is any risk acceptance that would outlive the
remediation deadline of the SLA profile (`--expires` beyond the SLA DUE date).

For a realistic multi-stage image (UBI 9 + Node.js) with OS and npm findings, vendor
*won't fix* packages and a rebuild that closes findings, run
[examples/ubi9-node](../examples/ubi9-node/README.md).

## 4. Ship the fix and let the evidence close findings

```sh
./bin/crane copy --platform linux/amd64 alpine:3.18.12 localhost:5555/demo/app:prod
sc monitor
```

Expect: `changed from <old digest>`, most findings `→ fixed` (evidence: the new scan),
the rest *carried over* to the new digest with their triage state, risk acceptance and
first-detection date intact.

```sh
sc findings list --all -o csv | cut -d, -f8 | sort | uniq -c   # fixed / superseded / open
sc findings show <a fixed ID>                                   # "absent from successor digest (evidence: scan #2)"
```

## 5. Report and health

```sh
sc report monthly -o html --out $DEMO/report.html && open $DEMO/report.html
sc report monthly -o md
sc report monthly -o csv --out $DEMO/remediation-plan.csv
sc health --all
```

Provoke health findings to see the self-monitoring:

- stop the registry and run `sc monitor` → `resolve_failed`, monitor run `degraded`/`failed`;
- set `health.db_max_age: 1m` in `$DEMO/config.yaml` → `db_stale`;
- pin a wrong checksum (`scanners.tools.grype.sha256: "00…"`) → `scanner_checksum_mismatch`;
- restart the registry (it comes back empty: re-copy the image) and run `sc monitor` again
  → the findings resolve on their own.

## 6. Regression

Move the tag back to the old image and run `sc monitor`: the previously fixed findings
come back as `reopened`.

## Clean up

```sh
rm -rf $DEMO
```
